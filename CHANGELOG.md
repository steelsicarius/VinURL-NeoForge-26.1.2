Version: 2.6.3-26.1.2 (NeoForge port)
- port: full port of VinURL 2.6.0 from Fabric 26.1 to NeoForge 26.1.2 (NeoForge 26.1.2.114, ModDevGradle 2.0.148, Java 25)
- port: owo-lib replaced with NeoForge APIs (CustomPacketPayload networking, ModConfigSpec + ConfigurationScreen, vanilla Screen rewrite, CompoundTag disc data)
- port: commons-exec replaced with in-repo CommandBuilder (no new dependencies)
- port: mixins kept and retargeted for 26.1.2 (JukeboxBlockEntity, Gui.setNowPlaying)
- fix: custom disc playback started and was killed ~2 ticks later — `JukeboxMixin.tick` compared the song ticks against `duration * 20` even with `duration == 0` (a fresh disc without pressing "simulate"), so the server sent a stop packet immediately after the play packet; duration 0 now means "play until the disc is ejected" (inherited flaw of the original logic, reproduced and verified in a controlled run)
- fix: `VinURLClient.CLIENT` was captured in a static initializer that can run before the Minecraft instance exists, so `SoundManager.playSound/stopSound` could throw NPE inside the `vinurl:play_sound_record`/`stop_sound_record` handlers and playback silently failed; the client instance is now resolved on every use (`VinURLClient.getClient()`)
- fix: `FileSound.getStream` failures were swallowed without logging by the sound engine; they now log the file, path and cause (ERROR level)
- enhancement: `playSound`/`stopSound`/duration-stop now leave DEBUG traces and a WARN when the sound engine refuses to start a sound
- enhancement: music_discs item tag now ships under data/minecraft/tags/item/ (the original's tags/items/ path was never loaded)
- change: silent placeholder sound is now an own vinurl:empty OGG (fabric-sound-api-v1 is not available on NeoForge)
- change: jar name format VinURL-<version>-<mcversion> (VinURL-2.6.3-26.1.2.jar)
